eBay / Channable-automatisering via een browser op de VPS · n8n eruit

vps2 = Hostinger srv1411336 (187.124.2.66) · Channable project 314525 · doel: terugkerende eBay/Channable-taken draaien op de VPS, zonder n8n en zonder cloud-LLM
Kernprincipe: n8n gaat eruit. De terugkerende Channable/eBay-acties draaien via een browser op de VPS met de al bewezen methode sessie-token → Bearer → app.channable.com/api/.../projects/314525. En de Duitse omschrijvingen komen uit een deterministische Channable-rule — dus daar is helemaal geen generatie-pipeline (n8n/Gemini) voor nodig.

Wat n8n deed → waar het naartoe gaat

n8n-taak (eruit)Vervanger
Basisomschrijvingen genereren (n8n/Gemini-pipeline)Deterministische Channable-rule DE - ebay_desc_de (template + velden). Geen LLM, geen pipeline — de feed maakt de tekst zelf.
Wekelijkse prijslijst-/feed-export (n8n)VPS-browser cron → Channable export (of Channable's eigen scheduled export). Levert het bestand zonder n8n-credential die verloopt.

Eventuele verrijking / vrije tekstLokale Ollama op vps2 (staat er al, naast OpenClaw/AnythingLLM). Blijft op de VPS, geen cloud.

Architectuur

Runner op de VPS

  • Eén extra Docker-container ccp-browser op vps2, naast de bestaande (OpenClaw, Ollama, AnythingLLM, traefik).
  • Headless Chromium + klein script (Puppeteer/Node) dat de Channable-sessie/token vasthoudt.
  • Scheduler = cron/systemd in de container — niet Cowork /schedule, niet n8n.
  • Output schrijft naar _connector/bridge/inbox/ (die inbound-route werkt al).

Taken die de runner draait

  • Dagelijkse scan → rules-state diff project 314525.
  • Rule-verify → titel ≤80, DE - ebay_desc_de actief, categorie-mapping.
  • Publish-trigger na goedkeuring.
  • eBay Seller Hub (browser, geen API) → order-/tracking-check waar nodig.

Concrete stappen om het neer te zetten

  1. Toegang: vps2 via Hostinger hPanel → Browser Terminal (root-shell, geen SSH-key nodig — zelfde route als de OpenClaw-recovery). Verse Terminal per keer (tokens zijn eenmalig).
  2. Container: ccp-browser aanmaken met headless Chromium + Node/Puppeteer.
  3. Channable-auth: het sessie-token als env op de VPS zetten (jij plaatst het, niet via de chat — §8). Script leest het en zet Bearer.
  4. Scan-script: de bestaande scan-methode porten (GET /rules/import/0, channels, quality) → dagelijkse diff.
  5. Cron: dagelijkse scan + diff → bridge/inbox. Wekelijkse export idem.
  6. n8n uitzetten: zodra de VPS-runner draait, de n8n-flows (o.a. prijslijst) deactiveren. Eén bron, geen dubbele/verlopen credentials.

Randvoorwaarden (eerlijk)

  • Ik kan dit nu niet zelf op de VPS zetten: de SSH-key is niet mountbaar en de Browser Terminal vergt jouw ingelogde Hostinger-sessie. Dit is het plan; uitvoeren doen we via de Browser-Terminal-route (zoals bij de OpenClaw-recovery).
  • Het Channable-token is een credential → dat plaats jij op de VPS, niet via mij.
  • VPS-security eerst hardenen: de audit vond de OpenClaw Control-UI met losse auth-flags. Zet die dicht vóór je gevoelige flows op de VPS draait.
