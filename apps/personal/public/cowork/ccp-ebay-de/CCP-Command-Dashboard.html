Dashboard ontgrendelen

eenmalig per browser

Orderdata, klantwoonplaats en Magento-cijfers zitten achter een slot. Vul je beheer-PIN in; deze browser onthoudt daarna een kijker-token en vraagt het nooit meer. Dat token kan geen sleutels lezen en je kunt het per apparaat intrekken.

Nog geen PIN ingesteld? Eenmalig in de Supabase SQL Editor — niet via dit scherm, niet via een chat: insert into cms_secrets(name,value) values ('ccp_dashboard_pin_hash', encode(extensions.digest('JOUW-PIN','sha256'),'hex')) on conflict (name) do update set value=excluded.value;

Read-only garantie. De backend accepteert voor Magento uitsluitend GET. Prijzen, voorraad en orders worden nooit vanuit dit dashboard aangepast — Channable blijft eigenaar van prijs en voorraad.
Twee soorten toegang, bewust gescheiden.
1 · API-sleutels worden server-side bewaard in Supabase cms_secrets — daar staan channable_api_token en magento_token al. Ze komen nooit in de browser terug: je ziet alleen of ze gevuld zijn en de laatste vier tekens. Automatiseringen (edge functions, n8n) gebruiken dezelfde bron.
2 · Login-wachtwoorden (eBay/Bol/ABS-portal) gaan hier niet naar Supabase. Dat is jouw eigen §8-regel. Ze blijven op deze machine en produceren een .env-regel plus een kant-en-klare Chrome-login-opdracht.
Na 5 mislukte pogingen binnen 15 minuten wordt beheer geblokkeerd; elke poging staat in het audit-log. Nog geen PIN? Zet die eenmalig in de Supabase SQL Editor — niet via dit scherm, en niet via een chat: insert into cms_secrets(name,value) values ('ccp_dashboard_pin_hash', encode(extensions.digest('JOUW-PIN','sha256'),'hex')) on conflict (name) do update set value=excluded.value;
